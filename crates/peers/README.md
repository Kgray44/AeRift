# AeRift v1 LAN peers

`PeerNode` serves pairing and file transfers over TCP, TLS 1.3 and HTTP/1.1. It uses rustls with its ring provider. Each native installation creates a P-256 self-signed leaf and derives its device ID from the leaf's DER SHA-256. The handshake requires proof of client key possession. Clients pin the target fingerprint before sending an invitation token or transfer request. TLS resumption and early data are disabled. Unknown but cryptographically authenticated clients can only reach the pairing route. Retaining an old connection or a sender handle cannot restore revoked trust.

Provide an atomic `SecretStore` backed by DPAPI on Windows or Keychain on iOS. Its `initialize` operation returns the value that won the write, including when another process initialized it first. An invalid stored identity or a save failure surfaces as an error. Identity replacement requires fresh pairing. The host also supplies a durable `TrustStore` for peer fingerprints and labels. A failed trust write leaves the pairing pending so the operator can retry or decline. Private keys and selected paths stay in the native process.

After binding the native listener, run `Discovery::start` with the actual bound port to advertise and browse `_aerift._tcp.local.`. The adapter merges the discovery snapshot with saved devices so the disappearance of a DNS-SD record marks a saved peer offline. Resolved advertisements are untrusted routing and display hints. Bind to the interfaces allowed by the host and configure local-network permissions and the Bonjour service entry on iOS. A copyable or QR-encoded invitation is identical on the wire. Use `invitation_peer` to select a discovered endpoint, or pass a receiver-provided socket address as a manual fallback.

Call `Discovery::stop` on graceful teardown so the daemon can repeat the DNS-SD goodbye before closing. Record expiry covers unannounced departures.

Create the invitation after the receiving operator requests pairing. It expires in five minutes. Call `confirm` in response to an explicit decision on the native pending request. The token is generated by the OS-backed CSPRNG and is held in memory. The host must keep it out of logs and telemetry. One fingerprint may redeem the invitation, with at most two retries before the original deadline. The listener caps concurrent connections and holds a separate limit for untrusted peers. Revocation removes stored trust, invalidates a pending or cached reply for that peer and cancels active local transfers.

Use `PeerNode::sender` for the authenticated destination and `Receiver::subscribe` for incoming offers. Convert native states to the app bridge contract in the host. The peer crate does not depend on the Tauri runtime.

The manifests declare Rust 1.89 as the minimum. The crates use Tokio for I/O/time, Hyper, Hyper-Util, HTTP Body Util and Bytes for bounded HTTP framing, Serde for v1 JSON, UUID for identifiers, SHA-2 for fingerprints and checksums, and tempfile for staged writes. The peer crate adds mDNS-SD, base64url encoding, ring-backed random invitation tokens, constant-time token comparisons via subtle, and rcgen plus x509-parser for the certificate profile. Both rustls and rcgen use ring.
