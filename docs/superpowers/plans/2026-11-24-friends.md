# AeRift Friends Implementation Plan

**Goal:** Transfer to an explicitly invited person without confusing their enrolled devices with My Devices or Nearby Devices.

**Architecture:** Independently scoped Ed25519 person authorities sign device enrollments and mutual consent; the sender durably assigns an offer to one eligible authenticated device before authorizing the payload. Integrate through a capability-gated cross-platform UI and Remote transport, never by widening LAN trust.

**Spec:** docs/friends.md

- [x] Test signed private invitations, bound responders, verification and expiration; build authority and local persistence seams in crates/peers.
- [x] Test concurrent and restarted device claims and per-device revocation; build sender-owned durable one-winner offer ledger.
- [x] Implement and test capability-gated Friends UI, desktop split and mobile list-detail; use existing Glass/Motion.
- [ ] Bind Friends wire messages and credentials to authenticated Remote sessions; link source selection, history and verified receipt end-to-end.
- [ ] Qualify Android, iOS, desktop, real distinct uplinks and offline regression separately.

Current draft exits after shared-core and frontend qualification. Native persistence and real network qualification remain open.
