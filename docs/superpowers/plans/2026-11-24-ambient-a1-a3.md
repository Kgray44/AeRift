# AeRift Ambient A1–A3 Implementation Plan

> For agentic workers: follow the implementing and test-driven-development workflows. Verification must identify the platform and exact revision.

**Goal:** Capture a deliberate selected object from its native context without changing the caller's foreground app; manage capture eligibility independently of the main UI.
**Architecture:** Shared context resolution and object freezing live in the transfer crate. OS adapters return candidates rather than app permissions or destinations. The Windows host retains the existing tray, network runtime and transfer protocol; any capture policy is driven by native state rather than decoration or focus events alone.
**Tech stack:** Rust, existing SHA-256 and v1 transfer, Tauri, Windows Shell COM and Windows session APIs.
**Spec:** `docs/ambient-a1-a3.md`.

## Global constraints
Default off. No simulated input, clipboard reads, screenshots, public lookup, implicit destination grant or changed v1 wire format. Existing file picker and desktop/mobile transfers continue independently.

## Review focus
- Explicit selections that are sensitive, unreadable, virtual, huge or changed must not silently fall through to other content.
- Multiple selections form one frozen collection; unknown native context fails closed.
- No local paths enter metadata or previews sent to peers.
- Native foreground or session changes must not substitute a different object.
- Camera suspension and actual Explorer behavior require physical Windows validation distinct from test fixtures.

## Tasks
- [ ] A2: test deterministic context priority, freeze bounded collections/manifests, implement verified streaming and v1 capability negotiation in the shared transfer crate.
- [ ] A3: native foreground and COM selection adapter, exact-window revalidation, test policy on synthetic paths, compile Win32 adapter; pass selected candidates through the same resolver.
- [ ] A1: independent policy state, session/power interlocks, tray pause/resume and actual camera status; verify which native or existing-window capture paths can operate without main WebView dependency.
- [ ] Verify locked shared Rust and Windows host; document physical evidence still needed before claiming end-to-end acceptance.
