# Windows selected-folder lab adapter

Base: #109 at `2fd5894`. Apply `candidate.patch` with context or manually port its small hunks; do not replace unrelated host or manifests from the staged snapshots. No production routes, default IPC, capabilities, or frontend are changed.

- Windows fixed NTFS, one explicit native folder picker and one held read-only scope per isolated owner. No child opening/navigation, file contents, import/transfer, labels containing the root path, writes, recent grants, directory watches, or persisted permissions. Normal folder selection for receiving is unrelated.
- Every invoke is bound to a local lab main webview; production host does not register this adapter. A lab builder must install the native dialog plugin, manage `WorkspaceFolderPicker::default()`, and at setup bind its only local `main` window via `bind_owner`. The fixture must create exactly one owning main webview with trusted bundled assets only, block navigation and secondary windows, deny remote origins in ACL, and use no exposed generic dialog, shell, filesystem, transfer or network commands. Keep lab registration source separate from the default host.
- Register only `workspace_choose_folder`, `workspace_list_chosen_folder` and `workspace_close_chosen_folder` in that isolated builder. Choose issues {grant,cursor}, list returns {entries:[{name,sizeBytes}],next}; a null size means directory, null next means complete. Rows are display metadata, not file authority. Label paths are not returned; render names as text and do not persist them. A cancelled or rejected picker does not replace a prior grant. Only one chooser can be active; closing the owner revokes the root and blocks late installation. Grant expires after five minutes; EOF/failure/replacement/revocation releases an existing grant.
- On hosted Windows with pinned dependencies and valid fixture assets, run `cargo test --locked -p aerift-transfer --features windows-folder-picker-qualification --lib folder::windows_handles::directory_page`, and then within `apps/aerift/src-tauri` run `cargo check --locked --features workspace-folder-picker-qualification` and `cargo test --locked --lib --features workspace-folder-picker-qualification workspace_folder_picker::tests`. If the project’s known test-binary loader error recurs, qualify compilation independently, then use an isolated Windows lab for app lifecycle verification. Run formatting checks in both manifests and `node --test tests/ui/workspace-folder-picker-qualification.test.mjs`.
- Runtime lab on disposable, synthetic NTFS only: choose a folder with a sibling sentinel; check pages and no sibling/child contents; compare cancelled picker with current active grant; wrong/replayed token and foreign label are refused without consuming the valid cursor; replace/revoke/close must release rename-pinned directories; let an idle grant expire without another invoke; close main while picker is pending and ensure late completion cannot install authority. Assert sandbox has no public network and production command path remains unavailable. Record Windows revision, fixture hash, install/launch and each result separately. Do not switch on ordinary UX until those checks pass.
