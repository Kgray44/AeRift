# Windows Workspace browser: offline runtime handoff

Standard hosted GitHub Windows is disposable but not independently offline. [GitHub explicitly does not support nested virtualization](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners), so do not presume Windows Sandbox can run on the current hosted image. Do not install path-based firewall rules or block outbound networking of a shared CI agent: those do not prove independent isolation and can interfere with the runner. Keep hosted compilation and pure policy tests as the default. The proposed fallback is a disposable Windows desktop guest with WebView2 installed beforehand and no virtual NIC at the hypervisor. [Windows Sandbox with networking disabled](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file) is a possible separate administrator-approved route only where supported and independently verified.

## Two-phase witness

1. Compile exact reviewed source using locked Windows Cargo; do not execute the ignored fixture in that environment. Locate the one native qualification test executable from Cargo JSON output, calculate SHA-256, record source SHA, target, SDK and toolchain, and seal the binary and script on a read-only virtual ISO. Do not include the checkout, credentials, personal data, installers or shared writable volumes.
2. In a separately provisioned, fresh Windows guest (not the owner's computer), preinstall a supported WebView2 runtime, shut down to remove all VM adapters, disable host file/clipboard/device sharing, then boot from a sealed disposable image. Attach the read-only fixture bundle. Verify the disconnected hardware configuration from the host management plane before launching. The guest script additionally checks no active adapter/default route and verifies the independently recorded hash. Guest checks alone, an invocation switch, and intercepting .invalid requests do not prove egress isolation.
3. Run `run-workspace-browser-offline.ps1 -ExpectedSha256 <receipt> -FixtureExecutable <sealed executable> -GuestIsolationAttested` from a clean environment. Capture exit status, synthetic counters/assertions and elapsed time from VM console or offline guest log; set a hypervisor watchdog and discard the guest (including its WebView2 process tree/profile) after collecting evidence. Do not connect a NIC to collect logs. No runtime dispatch was made; there is no confirmed provisioned target in current scope.

## Native viewport stage

The independently stageable viewport module owns the browser on the native STA. It admits a fully contained physical rectangle beneath trusted chrome, declines partial clipping, never requests focus, hides on obstructed/minimized/inactive states, refuses navigation while hidden, and drops the controller if layout or hide fails. The test default adds pure admission tests and the isolated fixture exercises present → popup hide → hidden navigation refused → close. No app commands, webviews, capability changes, renderer-derived bounds or policy changes are introduced. Real focus, mixed DPI, visual rendering and app wiring remain separately unverified; the geometry owner is not a release integration.
