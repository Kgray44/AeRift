# Workspace browser qualification request owner

Based on `0061d5c980ecee1e3604418d7e50a23611f5cce2`. This owner stays in the standalone qualification target; it does not serialize requests or register any caller, authority, IPC or production witness. `ClosedFixture` admits only the fixed synthetic start address, and the raw browser's current navigation policy still guards all subsequent navigation and request interception. The layout passed into the owner is calculated by the trusted native side, never by a page.

Presentation begins with a typed generation-bound ticket and `Accepted`, not a live view. Only a matching completion that passes the existing native `TrustedViewport` admission can produce `Presented`; dimensions are independently bounded before projection and are an acknowledged rectangle, not evidence of page load. Native layout hides obstructed views and invalidates an obstructed pending admission; after close/revoke, stale completions close their controller rather than reopening. No native back/forward/reload operation can be triggered in this slice. The owner does not decide egress or portability, and should not be wired to web content.

Portable qualification: `rustc --edition 2021 --test apps/aerift/src-tauri/src/workspace_browser_request_owner.rs -o request-owner-tests` then execute the test binary; the fake controller has no network/UI. Four tests passed on Linux. Existing ignored Windows smoke now composes the same real owner into the sealed fixture; do not run it without the separate approved network-isolated Windows runtime. Product composition, real Win32 presentation and focus, real environment isolation receipt, and an explicitly qualified navigation-history implementation remain open.
