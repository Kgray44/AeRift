## Physical Windows laptop ↔ iPhone run

1. Record the SHA, package/artifact checksums, build commands, OS/device models, architecture, WebView2 and Xcode versions, signing or distribution method, and network topology without private addresses. Install fresh builds on both devices. Launch both and verify they work without cloud sign-in.
2. Use ephemeral test identities and a receiver-owned test folder or sandbox. Put both devices on the same LAN. Deny iOS local-network access on first prompt, check the UI and retry after granting. Verify Windows firewall behavior with the normal private-network configuration and the app's expected permissions.
3. Confirm both apps resolve each other on the same IPv4 LAN with local network access. The current invitation resolves the inviter through discovery. If discovery fails, record which device could not resolve the other and capture the recovery attempt. Decline one invitation first and verify no saved trust. Approve a fresh invitation, restart both apps and verify trusted reconnect. Revoke and verify the previous pairing no longer permits sending. Re-pair with the other device initiating.
4. Run `node tests/acceptance/prepare-fixtures.mjs <existing scratch folder>` to create a fresh fixture folder with empty, binary, duplicate-name and 128 MiB files. The optional final argument sets a smaller size in bytes. Check available storage for the fixture and receiving copies before the run. Copy the fixtures to the device that will send them and verify each copy against `manifest.json` before sending. After transfer, hash the actual saved file on the receiving platform. On Windows use `Get-FileHash -Algorithm SHA256`. Send `duplicate-a/same.bin` and `duplicate-b/same.bin` to the same receiver folder and check both hashes.
5. Send by button in both directions. Before accepting, verify the destination has no new published file. Reject one offer and confirm zero publication. Accept fresh offers and compare hashes. Repeat with the empty, duplicate-name and large fixtures. Preserve and verify original contents after the duplicate-name case.
6. Cancel during an active transfer from each side, then interrupt a large transfer by briefly disconnecting the receiver from the LAN. Record both terminals, final file visibility, temporary-file cleanup where the adapter exposes it, retry behavior, and release of space. Repeat a successful transfer after reconnect. During a separate iPhone receive, force-quit AeRift, reopen it, and verify the Files destination contains no partial file. Where an instrumented build exposes a staging count, confirm the abandoned partial was removed at restart. Re-pair or reconnect as needed and verify a fresh transfer.
7. Deny camera access, check ordinary controls, enable camera and send by gesture in each direction. Confirm exactly one offer per intent. Repeat with tracking loss, blur and target change before release. Record privacy observations without recording or retaining camera frames.
8. During the large transfer, test usable navigation and cancellation, keyboard focus on Windows, VoiceOver and touch on iPhone, and reduced motion. Record theme and OS accessibility settings and any stall, loss of focus or dropped action. Compare idle and streaming input-to-render timing on both devices using the [native UI timing procedure](strategy.md#native-ui-responsiveness-benchmark).

Per case, record ID, UTC timestamp, SHA, both device builds, direction, fixture size and hashes, steps, expected and observed behavior, PASS/FAIL/NOT TESTED, and evidence reference. Redact invitations, identities, paths, personal filenames and frames.
