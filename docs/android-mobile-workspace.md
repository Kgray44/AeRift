# AeRift Android mobile workspace architecture

Android is an implementation target. The repository at `c09853d` contains native hosts for Windows and iOS and has no checked-in Android Gradle host, application entry, or Rust runtime adapter. This design keeps the mobile experience shared and assigns provider access, permissions, and lifecycle to Android.

## Platform boundary

Use the Tauri Android host with a Kotlin plugin. Give the app shell an explicit mobile platform selection and supply Android implementations of `AppPort` and the mobile workspace adapters. Extract shared UI only where both hosts use the same behavior. Keep the Home, Workspace, Rift, Devices and Activity destinations, Control Center, digital-object schema, and acknowledged transfer states in the existing contracts. Keep iOS and Windows entry points available throughout the work. [Mobile plugin development](https://v2.tauri.app/develop/plugins/develop-mobile/) · [Mobile qualification matrix](validation/mobile-workspace.md) · [v1 contract](../contracts/v1/protocol.md)

The Android plugin should return opaque asset handles, display names, byte counts and media kinds. Kotlin owns URI grants, Activity results, consent prompts and system surfaces. Rust owns pairing, trusted peer state, file transfer and integrity checking. JavaScript receives neither raw private paths nor a general API for opening arbitrary content URIs. A selected Android file produces an ordinary v1 selection. Ordered local groups can feed Rift one item at a time with the existing per-offer consent. The same verified transfer events drive progress, arrival and failure in the shared UI.

| Area | Android adapter and behavior |
| --- | --- |
| Files | Use the Storage Access Framework to open one or more documents through the user's chosen provider. Read with `ContentResolver`. Record whether the object is a provider reference, an app-owned import or a verified receive. Preserve a provider grant only where offered and intentionally needed. If the file moves, is removed or loses access, ask the user to locate it again. Export via a system create-document or share action. [Android documents and files](https://developer.android.com/training/data-storage/shared/documents-files) |
| Photos and videos | Use the system Photo Picker through `PickVisualMedia` or `PickMultipleVisualMedia`. Treat results as selected access only. Enforce the app's selection and byte limits after the picker returns because the fallback provider may ignore the requested count. Copy the bytes supplied by the provider for an ordinary file offer. Record the selected representation and qualify metadata and HDR behavior separately. [Android Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker) |
| Storage and preview | Stream provider objects into private staging with a bounded size check and release partial files on error, cancellation or process recovery. Store durable imports only when the user chooses to keep a copy. Present previews through a system viewer or a sandboxed media component. Use a grant scoped to the chosen file when handing it to a system viewer or share target. Publish received bytes after v1 integrity verification. |
| Notes and collections | Use the existing versioned object schema. Local notes, links, pins and collection membership remain usable offline. Media membership resolves asset handles through the native store. Show unavailable references and retain ordering. Carry note and collection copies as ordinary files until a common richer format is negotiated. |
| Browser | Open user-entered HTTP(S) addresses through Custom Tabs and use the browser's external-open affordance. Collect an address only through explicit user action. Retrieve browser downloads through the system picker. Keep remote pages outside the WebView that owns the Tauri bridge. [Android web content](https://developer.android.com/develop/ui/views/layout/webapps) |
| Clipboard | Read only after the user invokes Paste on a focused activity. Accept bounded text and readable image URIs. Do not retain an image grant after the action unless the user chooses to keep a copy. Keep history optional and sharing explicit. Suppress previews for marked-sensitive content and keep it out of history by default. [Android copy and paste](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste) |
| Peers and trust | Use Android network service discovery for the existing LAN service. Observe LAN permissions and service selection rules for the supported target SDKs. Discovery metadata is untrusted until the pinned peer is authenticated. Store the existing Rust identity and trust data in private storage protected by an Android Keystore-backed encryption key. Keep the existing TLS and pairing formats. [Android local network permission](https://developer.android.com/privacy-and-security/local-network-permission) · [Android Keystore](https://developer.android.com/privacy-and-security/keystore) |
| Lifecycle and gestures | Attach camera eligibility to the visible Rift, device capability, granted permission, and Control Center opt-in. On camera loss, backgrounding, or activity destruction, stop recognition and clear held-object state. For the first release, cancel foreground-only transfer work safely on app exit or loss of its supported network path. Reconcile the next activity view against Rust's authoritative snapshot. Keep manual transfer controls when camera behavior is unavailable. |

## Integration sequence

1. Generate the Android host in the existing Tauri app, pin the SDK and NDK versions in CI, and install an unsigned test APK on a phone emulator. Render shared destinations from a deterministic fixture before enabling native commands. Use Android back navigation and system-bar, display-cutout and IME insets in the host. Validate the same controls under contrast, system theme and motion preferences. [Window insets](https://developer.android.com/develop/ui/compose/system/insets)
2. Wire the Android platform guards and runtime adapter into the shared Rust host. Implement discovery start and stop, native identity and storage, and the existing watch, pair and transfer calls. Start with foreground manual Files transfers. Establish pairing and verify file hashes both ways with Windows before exposing gesture or background capabilities.
3. Connect the system pickers and export, then add durable imports, notes, browser, clipboard and collections behind capability-driven availability. Check cancellation, denied and revoked grants, provider failure, selection size caps, restart, removal and cleanup.
4. Qualify automatic gesture recognition and receiver readiness on a physical device. Map each recognition phase to the shared Rift presentation. Arrival and completion require verified receipts. Unsupported features stay disabled with a reason in Control Center.

## Release evidence

| Gate | Required evidence |
| --- | --- |
| Host and accessibility | Exact APK revision, Android and WebView versions, emulator screen captures, a phone and tablet layout check, TalkBack and keyboard navigation, display scaling, and reduced motion. |
| Provider safety | Cancellation and denial leave the prior selection available. Bounded copies roll back after interruption. A staged photo and video transfer with documented source and received digests. |
| Network and trust | Approve, decline and revoke pairing on a physical Android phone and Windows peer. Verify discovery loss and recovery, and compare hashes both directions. Test cancellation during transfer and verify partial cleanup. |
| Camera and lifecycle | Verify physical camera permission, foreground exit, rotation, hand acquisition and release, camera loss, and manual fallback. Compare Activity states to the corresponding backend receipts. |
