# A6: AeRift Browser Pickup (qualification)

The Chromium MV3 extension is shared by Chrome and Edge. It reads a single ordinary top-level HTTP(S) tab only on its own toolbar or browser context-menu action. Users must invoke it within the foreground browser; a camera/window event is not a browser authorization. It uses `activeTab` / `scripting` / `contextMenus` / `nativeMessaging` only: no global host grants, polling, persistent content scripts, history, cookies, request intercepts, private profiles, embedded frames, external websites calling the extension, or browser storage. Focused/window ID, active tab ID, canonical URL and document identity must match on a one-shot recheck; a new invocation supersedes previous in-flight attempts. Values copied into the request are immutable and aren't resolved from the next page. The very first DOM call observes the clicked active tab at execution time; if it already replaced the same URL before the first observation, there is no earlier document identity available from the toolbar event.

In order: one explicitly selected text range inside a single ordinary DOM text node, a link/media reference explicitly requested in the native context menu, the focus-selected playable media element's source reference, else a page URL reference. Refuse editable/password/form contexts, subframes/private windows, failed checks, overlimit values, and unsupported chosen representations instead of scraping other content. Selected text is literal UTF-8 and bounded to 16 KiB. Browser source and page/media/link **references only** are encoded as inert `text/uri-list` (HTTP(S), no credentials, query or fragment). The receiver should preview before the user opens a reference. URL paths can still contain sensitive data; users should only request pickup when appropriate. Nothing auto-opens or sends. Range formatting, multi-node ranges/collections, actual media/file bytes, download manager items, privileged/browser-internal pages, login-dependent page state and local file URLs are unsupported in this slice. It does not download, archive, restore or execute page HTML/scripts.

The Rust codec enforces exact well-formed configured extension ID on browser-provided origin, native-endian size before allocation (100 KiB max), a deny-unknown-fields v1 schema and stricter content bounds. It uses A2 `CaptureContext` and `FrozenCapture`/SHA-256 with no sender, connection or recipient authority. Chromium `allowed_origins` is the enforcement boundary for extensions; argv alone is not authentication against a directly launched same-user local process. The example host exists only for validation, returns a version/status response without captured bytes, then drops the snapshot. It never stores or exposes data to the shipping app. Product use requires a separately authenticated, opt-in native-host-to-app handoff and review/clear UX for the held object before any transfer.

## Deliberate manual qualification (not automatic installer changes)

Do this only in an authorized separate Chromium test profile/device using synthetic pages. Creator loads the unpacked `apps/browser-extension` folder and reads its extension ID from `chrome://extensions` or `edge://extensions`. Build a separately pinned example for the observed ID and generate the host manifest; use a separate manifest/binary per browser if IDs differ. Example in PowerShell from the repository root:

```powershell
$id = 'replace_with_observed_32_letter_extension_id'
$env:AERIFT_BROWSER_ALLOWED_ORIGIN = "chrome-extension://$id/"
cargo build --locked -p aerift-transfer --example ambient_browser_native_host
$hostPath = (Resolve-Path '.\target\debug\examples\ambient_browser_native_host.exe').Path
python scripts/ambient/browser_host_manifest.py --host $hostPath --extension-id $id | Set-Content -Encoding ascii .\aerift-browser-test-host.json
```

Only with explicit authorization, register the manifest's absolute path as the default value under test-account HKCU `Software\Google\Chrome\NativeMessagingHosts\com.aerift.ambient_browser` or `Software\Microsoft\Edge\NativeMessagingHosts\com.aerift.ambient_browser`. Do not overwrite an existing registration. Keep built binary and manifest in a trusted installation location. No script changes the registry. On restricted/missing host/version mismatch the action tooltip reports unavailable; check the browser's actual extension ID, the matching manifest `allowed_origins`, registered file path, and native executable's compiled origin. Retry deliberately using the action after repair; there is no stale capture or automatic retry. Use the only keys created by this qualification to revert when done. CI requires no registration or browser; its injected APIs and stdio fixtures do not prove real browser installation or host delivery.

Primary platform references: [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [Microsoft Edge native messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging).

### Confirmable application handoff contract

The next adapter can use `BrowserPickup`: a native issuer explicitly arms one UUIDv4 capability for at most 45 seconds, then accepts exactly one bounded full stdio frame and returns the literal, inert UTF-8 preview plus an independent review ID. A wrong, replaced or expired ticket, trailing bytes, private/unsupported source or malformed frame cannot replace the accepted preview. A deliberate local confirmation consumes the review ID within 30 seconds and returns the exact previously frozen A2 object. It does not grant a recipient, transfer, launch or any browser authority. Cancel, session lock, exclusion and host shutdown must clear the native slot; do not retain plaintext snapshots in credential or diagnostics files.

This contract is tested directly; an installed, private OS transport from the browser companion and the native permission/review UI are still absent. Chromium's allowed-origin manifest governs extension access to the companion, but it is not valid authentication of an arbitrary locally launched process. A future registered installer should transport the arm off the renderer IPC surface on a local-only, user-scoped named pipe (Windows) with one connection, ACL, bounded reads/deadline, and session identity. Keep companion proposals untrusted until an app-local explicit review, even with local ACLs. Do not send payload or ticket through command lines, inherited logs, static path-readable config, clipboard, a web-accessible local port or generic IPC shell event. Scheduled expiry belongs to the private native owner, not the browser page.

## Native Windows pipe transport qualification

The optional standalone `scripts/ambient/windows-browser-pipe-probe` binary runs an app-simulating parent and an explicitly spawned copy of itself. No browser host or Tauri app is registered or started. The pipe is first-instance only, remote-disabled and protected by a DACL for the current logon SID. Windows-reported client and server process IDs must match the two known subprocess endpoints before the test ticket is released. The child receives endpoint bootstrap via inherited stdin; neither a ticket, endpoint nor content appears in arguments, environment, files, logs or registry entries. After a bounded, schema-checked synthetic proposal, the fixture exercises the app-owned exact one-use review gate. The only operator-visible result is pass/fail. Run from a separately authorized Windows checkout (or use the matching hosted Actions job):

```powershell
cargo build --locked --manifest-path scripts/ambient/windows-browser-pipe-probe/Cargo.toml
python -I -B -c "import subprocess; subprocess.run(['scripts/ambient/windows-browser-pipe-probe/target/debug/aerift-windows-browser-pipe-probe.exe'], timeout=30, check=True)"
```

This proves a Windows-local transport for a child started by a known parent, not authentication of an independently launched extension host. A registered Chromium native host does not inherit this channel from AeRift. The offline test does not prove Chrome/Edge registration, app executable/provenance authentication, or Windows session and installer integration. A production design must establish those independently before disclosing an app arm ticket. Never rely on a public endpoint name, arbitrary browser-reported argv, PID alone, or a same-user DACL as an application identity or as permission to accept a transfer. Elevated and same-user injected process compromise are outside the fixture trust model. See [Microsoft named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights).
