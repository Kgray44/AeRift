# Chromium companion qualification and remaining app integration

The hosted qualification uses a fresh Chromium profile and a unique synthetic HKCU registration pointing to an exact fixture binary. Only the registry host name in the copied worker is test-specific; the real extension manifest, approved input permissions, action handler, data filter, native response framing, and Rust A2 freezing path are exercised. It invokes the toolbar action on a loopback-only synthetic document; unrelated page text and a password field are deliberate decoys. The compiled fixture emits only a yes/no receipt for the exact selected text if the pinned origin and capture kind match. A stale manifest origin and protected context must not return capture success. No captured bytes are written to disk, browser navigation is local, and teardown checks ownership before removing just the generated registry entry.

This is not the shipping Chrome/Edge add-on ID, installer support, real browser-profile qualification, or an end-to-end app bridge. Do not use this script on a user device. A hosted test neither publishes nor installs an extension into a real user profile and never opens the AeRift app.

## Smallest secure ordinary-app handoff

Keep Chromium's exact per-channel origin enforcement in installer-owned host manifests; no wildcard IDs or development public keys. Treat the browser companion input as a proposal, not transfer authority. Authenticate a product-side broker independently of browser argv and local pipe ACL. The app, not the companion or extension, owns an expiring one-use arm, exact frozen preview, confirmation and clear action. A native-verified connection and one-shot arm may stage a separately confirmed inert object; neither authorizes sending or opening it. Prefer an app-owned broker using product-signed executable identity, process-handle/creation-time and current-logon checks as defense in depth, together with a deliberately paired extension-side channel credential so no local listener or browser-controlled argument alone confers authority. Do not add remote HTTP, long-lived grants, ambient clipboard reads, or browser storage of content. A signed helper and scoped native proposals do not make arbitrary same-user process compromise in scope.

A permanent release needs separate Chrome and Edge extension identity/ownership, a deliberate user/browser install with signing, trusted companion registration and upgrade/uninstall ownership tests, an authenticated app bridge with one-shot review, and controlled installed-app validation on each platform. Keep the qualification registration and fixture host out of any installer. Use [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [Edge native messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging), and [Puppeteer extension action testing](https://pptr.dev/guides/chrome-extensions) as protocol references.
