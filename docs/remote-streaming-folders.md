# Remote streaming folder core

The shared folder core encodes one explicitly frozen Ambient directory as a bounded canonical manifest followed by verified file ranges, reusing the existing consent, retry, checkpoint and receipt machinery. The sender no longer makes a second on-disk copy or loads a whole file/archive into memory. The index is bounded to 1,024 entries and a 1 MiB encoded header. Payload is capped at 16 GiB including the header, subject to potentially smaller Ambient capture and receiver session limits. Upload memory uses a checkpoint buffer and one Ambient content block; preparation retains the manifest index and the existing 32-byte hashes per frozen file block.

A lost write response is reconciled through the authenticated receiver checkpoint. A repeated send with the same transfer ID and same prepared manifest begins at the acknowledged offset. The provider reads and verifies only the backing blocks touched by a checkpoint. After capture, extra source files are not included. A changed file fails closed. Empty directories are retained. The sender hashes the full virtual object before offering it; preparation is a bounded-memory read, not instantaneous.

The selected folder capability is explicit and never inferred from a filename or extension, but this cut does not implement application-level capability negotiation or enable a Folder button. The receiver will stage only a completed transfer receipt in its existing Remote scope. The checked private stage does not auto-extract or publish into the user's file tree. It checks canonical metadata, total bytes, individual SHA-256 hashes, whole-envelope SHA-256, revoked receipt, portable relative names and unique case-folded paths before returning a delete-on-drop directory. Conservative first-version ASCII-only paths avoid cross-platform Unicode aliases. Receivers require profile-private scratch with sufficient capacity for the v2 envelope and the staged output; the sender does not need archive scratch.

Qualification is local: the integration fixture uses the actual v2 sender/checkpoint/acceptance/receiver and deliberately drops three committed checkpoint HTTP responses, at offsets 0, 1,048,576 and 2,097,152. It verifies both receipts and actual digests, empty directories, skipped late entries, and rejection before consent and on changed received bytes. This is not a claim of WAN or installed app folder interoperability. Advertised/consented object type, atomically exporting a tree without overwrite, cross-platform filesystem policy, and independent-uplink evidence remain separate release gates. No route, relay, account or listener is added here.
