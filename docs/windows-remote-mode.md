# Windows Remote transfer mode

This is an opt-in mode in the standard AeRift Windows installer. It does not require a developer build or a command-line flag. It supports a single file at a time between invited devices over a pre-existing authorized private overlay exposing an IPv4 address in 100.64.0.0/10 (for example Tailscale), using an explicit port 1024–65535 on each device. The address range alone does not verify the VPN provider. Both people must verify their local interface and share addressing and fingerprints privately.

1. In AeRift, open **Control Center → Remote transfers over a private VPN**. Enter this device’s exact overlay address and port, authorize it and save. Finish any current transfers first. Exit AeRift with the offered button and reopen it on both Windows computers. Neither listener is started automatically in Remote mode.
2. On each computer, authorize that exact VPN listener and choose **Start Remote**. Compare the device fingerprints through a trusted channel. One person creates an invitation restricted to the other device’s fingerprint and shares the code privately. The other person enters the inviter’s exact address, separately verified fingerprint and invitation code. The inviter confirms the requester. Invitation expiry is five minutes.
3. Choose the authorized device, confirm its VPN endpoint, and pick a file. The receiver must separately accept the offer. A successful sender message means the authenticated receiver checked the file digest and saved it. Received files land in AeRift’s local data under `RemoteReceived`.
4. **Stop Remote** stops the private listener and cancels work. Remote revocation does not revoke Nearby pairing. Select **Use Nearby after reopening** and fully exit/reopen to go back to Nearby.

The two modes are mutually exclusive in a process. Missing or invalid settings are treated differently: missing settings preserve normal Nearby startup, while unreadable or invalid saved settings allow neither listener until reset. Saving only affects next launch. Remote has no discovery, online indicator, wildcard address fallback, camera, gesture, automatic NAT/relay selection, system-background queue, or direct public internet mode. Existing single-file reconnection is session-scoped on this Windows path; no persistent sender queue or restart resume. Windows uses the existing protected device profile and a distinct Remote grants store. This change does not ship, install, expose or configure a VPN or relay.

## Independent-network qualification

Use two separately authorized Windows hosts on genuinely different uplinks (e.g. a cellular hotspot and a wired home connection) with an already-approved private VPN. Use a non-personal synthetic file larger than two transfer checkpoints. Manually verify exact overlay addresses on each host, stop any earlier qualifier instances holding the same AeRift profile, and use the workflow above. Confirm a refusal uploads no file; then accept a fresh offer. Report if receipt succeeds and compare both endpoint SHA-256 digests. Try interrupting the approved VPN route temporarily during a larger transfer and report the final receipt and the acknowledged offset if captured. Verify Stop and Remote revoke independently, and switch back to Nearby to confirm offline local functionality. Never upload logs with endpoint addresses, invitation codes, device private keys or household data. No independent-uplink test is implied by native or loopback CI.
